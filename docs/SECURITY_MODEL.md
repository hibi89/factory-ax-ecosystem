# Factory AX Security Guard · 보안/위협 모델 v1
> 2026-11-12 KST. 실제 보안인증·취약점 검사 통과/폐쇄망 동작 보증 아님. 안전 원칙은 **W1부터 필수**, 자동화 집행 레이어는 W3 이후 기능 확장.

## 보안 목표 및 신뢰 경계
- 목표: 지원되는 일반 Windows 업무 PC/별도 승인된 온프레미스 환경에서 **최소 접근·최소 저장·최소 실행·감사 가능한 결과**. 원본 자료·ERP·MES·PLC/SCADA를 변경하지 않는다.
- 외부 모델/API에 회사 데이터를 보내지 않는 것은 기본 설계. 단, 오프라인이 곧 정보 유출 원천 차단·침해 불가능을 의미하지 않는다. 사람/USB/공급망/OS·모델·PDF/Excel 악성 파일 등 위협은 남는다.
- 구분: `고객 제공 자료(신뢰하지 않는 입력)` → `범위 지정 parser` → `검증된 파생 데이터` → `내부 제안/판정` → `정책 승인` → `제한 실행` → `감사/복구`.
- 데이터 분류: 고객 승인 export 일반자료, 개인정보/영업비밀, 방산/제한자료, 코드/스크립트, 실행 자격·비밀. 데이터 클래스마다 승인 프로세스·저장 기간·암호화·반입이 다름. 방산/고보안 자료는 초기 상품이 지원하지 않음.

## 위험/대응
| 위협 | 방어 | 실패 시 |
|---|---|---|
| 의도치 않은 외부 통신·원격 전송 | 외부 DNS/CDN/telemetry/updater 호출 기본 비활성, 로컬 네트워크 검사·SBOM | 검사 중단, 로그 최소 기록, 설치 재평가 |
| 폴더/UNC 경로 탈출, junction/symlink, race | customer allowlist/실제 경로·파일 재읽기 SHA/handle 권한·바이트 제한 | fail-closed/BLOCKED, 원본 보존 |
| 악성 CSV 공식/Excel 매크로/스캔 PDF·압축 폭탄 | 포맷 sniffing, 확장자+MIME·용량/깊이/압축 제한, 내보내기 수식 이스케이프, 매크로 실행 금지 | 처리 차단·사용자 승인 요구 |
| LLM 환각/프롬프트 인젝션 | 문서 본문=데이터, 계획/도구/정책 승인과 분리, 근거 부족시 보류, 테스트 gold 세트 | 답변 보류, 권한 상승 금지 |
| 계획·승인 바꿔치기/역할 상승 | 정책결정은 런타임에서 실행 전 **subject+asset+action+parameter+plan sha+expiry+nonce** 재평가; OS ACL/프로세스 격리 | DENY/감사/강제중지 |
| 예약 작업 중복·재시도 부작용 | 업무별 idempotency, outbox/checkpoint/원본·목표 상태 확인, bounded retry | HOLD·관리자 재검증 |
| PC CARE 진단 영향 | 일반 업무 PC만 수동 read-only 우선, 시간대·자원 제한, 설치·실행 사전승인 | 검사 취소, 자동 수리 금지 |
| 코드 검사 범위 누락 | 허가된 코드만 정적 분석, 언어/rule/오탐·미탐 공개 | 고위험 코드는 전문 리뷰 요구 |
| 오프라인 설치/업데이트 패키지 위변조 | SHA-256·서명(가능할 때)·권리/SBOM·신뢰된 반입 경로·rollback | 설치 거부, 이전 패키지 유지 |
| 권한 없는 내부자·보고서 유출 | 역할별 접근·최소 수집/마스킹, 기본 local-only, 다운로드 정책, 보관·삭제 절차 | 경고/감사·계정 확인 |

## 권한 단계
- **T0 READ_ONLY**: 지정된 파일/폴더 조회·검색·해시·로컬 보고서. 기술적 안전 경계·고객 허가 필수.
- **T1 DERIVED_WRITE**: 기존 원본과 분리된 새 보고서·파생 SQLite 삽입; new-only 경로와 overwrite deny, 정책 승인.
- **T2 BUSINESS_WRITE**: 업무 데이터·외부 시스템 변경. W1 범위 제외, W3 보안·복구·합의·사람 승인/사후 확인 통과 필요.
- **T3 SYSTEM_REPAIR / OT_CONTROL / SECURITY_CHANGE**: **현 상품 설계의 기본 금지 영역**. AI 자율 실행 금지, 필요하면 별도 독립 안전/산업·법규 승인 프로젝트.
- `SOVIA`는 권고형 위험/감사 계층. 실제 `Security Guard`는 독립 정책 결정·실행 차단과 OS 안전장치가 있어야 함. SOVIA PASS가 실제 권한 인가라고 주장하지 않는다.

## 오프라인/폐쇄망 고객 인수
1. 설치 대상(업무 PC와 OT/안전제어망 분리)/OS·보안정책·하드웨어·패키지 반입 승인 기록.
2. 패키지 SHA·서드파티 목록·서명/해시·악성코드 검사·취약점/지원 종료일 검토.
3. 설치 전/후 서비스·포트·자동실행·예약작업 변경 기록과 고객 승인. 네트워크 비연결 테스트와 권한 없는 파일 접근 거부 결과.
4. 읽기전용 검사와 출력 폴더 경계·원본 해시 불변·한글 경로·장기 실행/중단·복구·시스템 자원 영향 시험.
5. 로그·개인정보 최소화·보존/파기·암호화·책임 경계·고객 보안감사 자료 제공.
6. 모든 실패/불확실성은 상태로 보고; '100% 보안/무유출/인증 획득' 광고 금지.

## 고위험 변경 통제
보안정책/OS 방화벽/백신/서비스/레지스트리·사용자 그룹·고객 보안프로그램/네트워크 경로/키 관리, 외부 서버, OT 접속, 수리/삭제/자동 patch 모두 사전 명시적 고객·사용자 승인 없이는 수행 불가.
