# 고객 납품·운영·장애복구 Runbook (설계)
> Factory AX 상용 설치/운영 경험은 아직 없음. 아래는 공급자 실행 체크리스트이자 고객과 합의할 인수 범위.

## 1. 계약/납품 이전
1. 공장/기업 담당자와 구매자 권한·보안 담당/PC 관리자·실제 사용자를 구분. 계약에는 기능·기기/OS·자료 형식·양식 건수·작업 범위·지원기한·비용/현장 출장을 명확히 한다.
2. OT/PLC/SCADA/MES 설치·쓰기·침입 탐지/백신 인증·방산 제한 자료 여부 사전 체크. 해당되면 초기 상품은 No-Go 또는 정식 별도 보안·안전 평가.
3. 고객이 직접 합성/비식별 데이터로 자기 업무 형식 샘플을 준비하도록 안내. 실제 원본은 승인된 고객 환경에서만 열람; 판매자 로컬 PC·외부 AI·Github 반출 금지.
4. 고객 PC/정책: Win10/11 버전, AV/서명, 권한·로컬 디스크 여유, 네트워크 폐쇄 여부, 허용 출입/설치/업데이트 정책, 단순 자산 식별자.

## 2. 설치/초기 설정
- release candidate: 검수한 source SHA + 공급망 목록/SBOM/라이선스 NOTICE/설치 파일 SHA + offline installer (정식 서명 여부 명시).
- 고객 관리자 승인→설치 패키지 해시 확인→필수 서비스/포트·예약작업 신규 생성 여부 제로/목록 기록→허가된 작업 폴더 지정.
- Factory Configurator에서 승인된 열 매핑·단위/LOT/수량·부분 출하 규칙 저장, 정책 버전/원본 해시·승인 로그 작성.
- 샘플 정상/오류/빈/변조 데이터로 각 상태 검증 후 고객 담당자 서명/인수 결과표.
- 외부 연결 실측, 원본/기존 앱/ERP/설비 시스템 바이트·설정 불변 증명.

## 3. 운영
- 수동 VERIFY 기본. 고객이 허락한 경우에만 Windows 작업 스케줄러로 **최소 read-only** 업무 PC 검사/보고. OFF/sleep/실행 실패/권한 상실은 지연 또는 HOLD, missed run 기록.
- 설정/정책 변경은 새 버전·검수·승인. 실제 파일과 매핑 변경 시 기존 서명된 결과 재사용 금지.
- 보고서/로그: 상태/오류코드/근거 SHA만 기본; 고객 비밀/인사·운영상 민감행은 최소화·접근권한·보존/파기 지정.
- PC CARE와 Code Checker는 옵션, 서비스 종료/과부하/부팅 장애/무인 수리는 허용되지 않는 기본 기능.

## 4. 장애/보안 사건
- 중단 단계·로그/검사 대상 SHA/프로필·버전/시각, 고객 승인 범위 확인. 실제 고객 자료를 채팅/외부 티켓에 붙이지 않음.
- 원인 계층: 파일/권한/원본 변경→전처리/스키마→규칙/정확도→GUI/설치→SQLite/복원→스케줄/Guard→OS/보안/서드파티.
- 오류 수정은 원본 상태 유지하고 별도 복사/합성 재현으로. 결과 출력을 덮어쓰지 않고 새 버전 패키지 및 독립 검증.
- 백업/복구: 고객 승인 위치에 스냅샷·체크섬, 원본과 restore 대상 분리, 데이터를 실제 비교한 후에만 SUCCESS; 실패 시 기존 정상 데이터/버전으로 되돌림.
- 보안/정보 유출 의심 시 승인된 사내 절차로 대응; 임의로 로그·자료를 클라우드 업로드하지 않음.

## 5. 업데이트/유지보수/종료
- 작업 중지/승인→기존 상태/DB 백업→업데이트 해시/라이선스 검수→offline update/롤백 검증→수락.
- 고객 자료는 고객 자산. 구매 계약·법정 보존 의무에 따라 최소 기록/파기/내보내기. 판매자 측 원본 보관·장기 무조건 보증 금지.
- 고객이 라이선스/지원 만료/회수를 요청할 경우 기능·고객 소유 결과·백업/제거 범위를 명시, 개인정보·비밀 산출물 재사용 금지.

## 6. 실제 납품 패키지 필요 항목
`FactoryAX-Installer` + SHA/버전 + 출처/OSS NOTICE/SBOM + 설정/검수 템플릿 + 사용/관리자/보안 안내 + 설치/삭제/백업/복구 + 성능/지원 범위 + 합성 검증 샘플/정답 + 고객 인수서 + 장애 대응 절차. 현재 파일은 **미생성**.
